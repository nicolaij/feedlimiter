# AGENTS.md

Прошивка ESP-IDF для блока контроля скорости подачи пилорамы «Piloramka»: измеряет ток пильного двигателя, работает PID-регулятор, задание на частотный привод выдаётся через DAC. Два окружения: контроллер ESP32 и выносной дисплей ESP32-C3 (ESP-NOW). Комментарии, строки UI и инструкция — на русском.

## Сборка и прошивка

```sh
pio run -e esp32doit-devkit-v1   # контроллер
pio run -e c3-display            # только дисплей (-DDISPLAY_ONLY)
pio run -e <env> -t upload
pio device monitor               # 115200; log2file также пишет logs/device-monitor-*.log
```

- Всегда указывайте `-e`; обычный `pio run` собирает оба окружения.
- Зафиксировано: PlatformIO Core 6.2, espressif32 6.13.0, ESP-IDF 5.5.3.
- CI и проектных тестов нет. Проверка = сборка + проверка на железе.
- `.pio/build/*` создан на Windows (пути `C:/Users/...` в CMake/ninja). В WSL этот каталог переиспользовать нельзя; выполните `pio run -e <env> -t clean` либо собирайте из Windows. Не редактируйте `.pio`, `.vscode/c_cpp_properties.json`, `compile_commands.json`.
- `src/CMakeLists.txt` глоббит `src/*.c`; новые `.c` подхватываются без правки CMake.

## Конфигурация

- `sdkconfig.<env>` — реальный Kconfig, который использует CMake (`SDKCONFIG=.../sdkconfig.<PIOENV>`); `sdkconfig.defaults` только задаёт начальные значения. Меняйте существующую настройку в обоих env-файлах либо через `pio run -e <env> -t menuconfig`.
- Оставьте CPU на 80 МГц и `CONFIG_FREERTOS_HZ=1000`; цикл управления рассчитан на тик 1 мс и цикл 20 мс.
- `managed_components/` в .gitignore и скачивается заново: не редактировать. Драйверы `button`, `led_indicator`, `ht16k33`, `tm1637` подключаются из registry через `src/idf_component.yml`. Локальный `components/pid_ctrl` — единственная оставшаяся копия драйвера: `src/adc.c` использует её внутренние поля (`Kp`, `Ki`, `integral_err`, `previous_err2`), поэтому не заменяйте её стоковым компонентом.
- `dependencies.lock` генерируется и игнорируется git; при смене env в нём локально меняется `target:` (`esp32`/`esp32c3`), в репозиторий этот файл не попадает.

## Архитектура

- `src/main.c:app_main` инициализирует NVS/меню, создаёт `xQueueDisplay` и пять задач: `adc_task` (управление; отсутствует в DISPLAY_ONLY), `button_task`, `console_task`, `display_task`, `wifi_task`.
- `src/adc.c` — контроллер: непрерывный ADC 20 кГц по каналам тока и задания, усреднение раз в 200 мс, позиционный PID, DAC1 = команда подачи, DAC2 = задание/индикация. Также отправляет `displ_t` по ESP-NOW.
- `run_stage` — общее состояние: 1 ожидание пуска пилы, 2 стабилизация, 3 запоминание тока ХХ, 4 холостой ход, 5 пиление под PID; 100/101/102 принудительно DAC 100/50/0%, 110/111 подмена тока, 999 перезапуск ADC.
- `src/terminal.c:menu[]` — единственный источник настроек. Значения хранятся как float-blob в NVS в namespace `storage` по ключу `id`. Значения `.val` действуют только на чистой NVS; на устройствах уже сохранённые значения остаются. Неизвестный/опечатанный id молча читается как 0.
- Консоль и веб-UI строятся из `menu[]`. `get_menu_val_by_id()` ограничивает значение `min`/`max`; `set_menu_val_by_id()` проверяет только конечность и согласованность пар.
- `adc_task` кэширует параметры при старте и перечитывает их только при `parameters_changed`, который выставляют сеттеры консоли/веба. Новый параметр нужно добавить и в этот блок перечитывания.
- Индексы меню значимы: 0 — номер устройства, 1/2 — упакованные `MAC1`/`MAC2`, индекс 2 скрыт в HTML, пункты консоли 51–55 захардкожены. Новые параметры добавляйте в конец; вставка до индекса 2 ломает MAC и нумерацию консоли.
- `src/network.c` — SoftAP + httpd: `/` форма настроек (POST сохраняет и перезагружает), `/update` OTA, `/ws` поток отладки. HTML встроен в C-строки; страница `/update` — читаемая `static const char[]` с HTML-строками. OTA принимает прошивку (первый байт `0xE9`) или SPIFFS-образ ровно `0x50000` байт, который пишется через следующий OTA-раздел (размеры совпадают с `partitions.csv`).
- Дисплей сам определяет HT16K33 по I2C, иначе TM1637 на тех же пинах. `c3-display` принимает `displ_t` по ESP-NOW (broadcast) и не запускает контур управления. Пины различаются по env в `include/main.h`; контроллер передаёт данные только при заданных `MAC1`/`MAC2`; сборка DISPLAY_ONLY инициализирует ESP-NOW всегда, используя broadcast.
- WiFi включается по одиночному нажатию `BTN_PIN` либо автоматически со скрытым SSID, если задан MAC дисплея. Второе нажатие перезагружает. SoftAP: `Piloramka<idn>` / `123123123`, обычно http://192.168.4.1/.

## Подводные камни

- Рабочее дерево в CRLF, а блобы в git — LF, поэтому `git status`/`git diff` показывают почти все файлы изменёнными. Реальные изменения смотрите через `git diff --ignore-cr-at-eol`; не пересохраняйте и не форматируйте файлы целиком, не коммитьте переводы строк. При правках сохраняйте CRLF.
- На момент написания в `src/*.c` и `sdkconfig.*` есть реальные незакоммиченные правки. Никогда не делайте `git checkout .`/`reset --hard` ради «очистки» CRLF-шума.
- Корневой `.docx` — русская инструкция по эксплуатации и наладке. Там есть схема подключения и старые названия параметров (например, `ADCk1`); для текущего поведения истина — код и `menu[]`.
